# 图表选型指南

先想清楚**这块要让读者看出什么**，再选图。图是为结论服务的：同一组数据，想说“谁最大”用排序条，想说“变化”用折线，想说“占多少”用环形或方格。

本指南参考了 FT 图表词汇表（Financial Times Visual Vocabulary）的九类关系、data-to-viz.com 的常见错误清单，以及 AntV 信息图的信息结构分类，按本技能的版块重新整理。

## 一、按“想说明什么”选

### 数据关系（有数字）

| 想说明 | 首选版块 | 也可以 | 别用 |
|---|---|---|---|
| **谁大谁小、排名**（量级、排序） | `bars`（排好序）、`ranking`（带 logo） | `bars style:"lollipop"`（条很多、长度接近时）、`columns`（类别少且是时间） | 饼图、雷达 |
| **随时间变化**（趋势） | `line`（连续、点多）、`columns`（点少、强调每期的量） | `years`（3–8 年）、`sparks`（多个指标各看趋势）、`columns stack:true`（总量和构成一起变） | 面积堆叠多于 3 层 |
| **前后两个时间点对比** | `slope`（看排名或方向变化） | `dumbbell`（看差距大小）、`bars` 两项 | 两条线的折线图 |
| **偏离基准**（高于 / 低于目标、均值、常态） | `deviation`、`beat`（实际 vs 预期） | `heatmap`（多日、多项）、`stackbar diverging`（问卷态度） | 普通柱状图配一条均线 |
| **占整体多少**（部分与整体） | `donut`（≤6 项）、`mix`（一条 100% 条 + 量价说明） | `treemap`（项多或有分组）、`waffle`（“每 100 人里有几个”）、`holdings`（持仓）、`stackbar`（多组构成对比） | 3D 饼图、超过 6 块的饼 |
| **单个百分比 / 完成度** | `rings` | `waffle`、`kpis` | 仪表盘指针 |
| **一个总量怎么拆出来**（加减拆解） | `waterfall` | `flows`、`mix` | 堆叠柱 |
| **流程中一步步流失**（转化） | `funnel` | `bars` | 饼图 |
| **从哪来到哪去**（流向） | `sankey`（多对多）、`flows`（一到多） | `waterfall` | 箭头满天飞的示意图 |
| **两个变量有没有关系**（相关） | `scatter`（加 `size` 就是气泡图） | `scatter quadrants`（分四类）、`line` 两个系列 | 双纵轴折线 |
| **多维度综合比较** | `radar`（≤3 个对象、5–8 个维度） | `heatmap`（对象多时）、`compare`（两个对象） | 超过 3 个系列的雷达 |
| **分布 / 区间**（最低到最高） | `dumbbell`、`target`（各家目标价） | `columns`（直方图：x 写区间） | 只给平均数 |
| **多个指标的近况** | `sparks`（小多图） | `kpis` 加 `rows` | 一张图塞十条线 |
| **地理分布** | 暂不支持地图：用 `bars` 按地区排序，或 `heatmap` 地区 × 时间 | | 没有归一化的地图 |

### 信息结构（文字为主，没有或很少数字）

| 想说明 | 首选版块 | 也可以 |
|---|---|---|
| 事情按时间怎么发展 | `timeline`（竖排，事件多；横排 ≤6 个） | `steps` |
| 怎么做、按什么顺序（流程、教程） | `steps`（≤5 步横排，多了竖排） | `timeline` |
| 循环往复的过程 | `cycle`（3–6 个阶段） | `steps` |
| 两个方案 / 产品 / 公司比较 | `compare`（逐项对比用 `rows`，优缺点用 `items`） | `radar`、`bars` |
| 按两个维度分四类（优先级、SWOT） | `quadrant`（SWOT 写 `swot:true`） | `scatter quadrants`（有数字时） |
| 总分结构、分类、原因拆解 | `tree`（最多 3 层） | `chain`（每类下是公司时） |
| 层层递进、基础到高级 | `pyramid`（3–5 层，上窄下宽） | `steps` |
| 并列的几个要点 | `cards`（带图标）、`points`（带标签） | `notes` |
| 一个结论或提醒 | `callout` | `banner`（一个大数字） |
| 名单（公司、人、产品） | `chain`、`chips` | `cards` |

## 二、各图的数据要求和上限

| 版块 | 适合的数据 | 上限 / 注意 |
|---|---|---|
| `bars` | 一组类别 + 一个数值 | 先排序；类别名长时比柱状图好；≤12 行 |
| `columns` | 时间或少量类别 + 1–3 个系列 | 必须从 0 开始；分组 ≤3 个系列；预估用 `est_from` 变淡 |
| `line` | 连续时间序列 | ≤4 条线，多了用 `highlight` 突出一条；点少于 4 个改用 `columns` |
| `donut` | ≤6 项的构成，合计有意义 | 多出来的并进 `other`；中间放总数 |
| `treemap` | 6–20 项的构成，可分组 | 面积难精确比较，关键数字另写出来 |
| `waffle` | 一两个整数比例（“100 人里有 41 人”） | 比例不是整数时四舍五入，说明里写准确值 |
| `stackbar` | 多组之间比较构成 | 类别 ≤5 个；问卷态度用 `diverging:true` |
| `scatter` | 每个对象两个数值（可加第三个 `size`） | ≤30 个点；只给重点点加标签；气泡面积而不是半径对应数值 |
| `slope` | 每个对象两个时间点 | ≤10 个对象；突出 1–2 个 |
| `dumbbell` | 每个对象两个值（前后、最低最高） | 按差距或终值排序 |
| `radar` | 1–3 个对象 × 5–8 个同量纲维度 | 维度要用同一刻度（如都是 0–100 分） |
| `sankey` | 两到三层的流向，每条有数值 | 节点 ≤12 个；数值要守恒（流入 = 流出） |
| `funnel` | 依次递减的阶段 | 阶段 ≤6 个 |
| `heatmap` | 行 × 列的矩阵 | 行列 ≤8；格子写数字，颜色只表示方向和强弱 |
| `sparks` | 3–9 个指标各自的序列 | 每张卡片自己的纵轴，不能互相比较高低 |

## 三、常见错误（发布前对照）

1. **没排序**：类别没有自然顺序时按数值从大到小排。
2. **截断纵轴**：柱状图、条形图必须从 0 开始；折线图可以不从 0 开始，但要标刻度。
3. **意大利面图**：一张折线图超过 4 条线。突出一条，其余变灰，或拆成 `sparks`。
4. **饼图分太多块**：超过 6 块、或几块大小差不多时，改用 `bars`。
5. **双纵轴**：两个不同量纲的系列别叠在一张图里，拆成两张或换 `scatter`。
6. **无意义的颜色**：颜色只用来表示分类、方向或强调。只有一个系列时用一种颜色；要突出一项时，其余变灰。
7. **彩虹色表示数值大小**：数值深浅用同一色相的深浅（`heatmap` 已经这样做）。
8. **面积和半径搞混**：气泡、方格按面积对应数值（`scatter` 的 `size` 已经按面积算）。
9. **3D、阴影、装饰**：不用。
10. **让读者心算**：差值、增长率、占比直接算好写出来，别只给两个数让读者自己减。
11. **合计对不上**：占比加起来要约等于 100%，拆解各项加起来要等于总数。
12. **没有标注**：每张图至少有一个结论写在小标题里，关键点直接标数值。
13. **同一样东西在不同图里颜色不同**：同一家公司、同一类别在整张海报里保持一个颜色。
14. **示意图冒充数据**：没有真实数据就不画曲线；科普里的模式图要写明“示意”。

## 四、标注与强调

- 小标题写结论（“房租越贵，通勤越长”），`note` 写单位和口径，`caption` 写数据来源或需要提醒的口径差异。
- 要突出的一项用 `highlight`（条、线、点、坡度、雷达都支持），其余自动变灰。
- 关键数字直接标在图上；图例只在有 2 个以上系列时出现。
- 涉及公司时给条、线、点、卡片加 `company`，自动带 logo。

## 五、现有版块都不合适时：`draw`

用 `draw` 自己画，模板会在卡片里给一块指定高度的画布，并执行 `js`：

```json
{"type": "draw", "title": "典型的一晚", "height": 230, "js": "const C=new PK.Chart(w,230); C.svg(`<rect x='0' y='0' width='${w}' height='10' fill='${PK.ACC}'/>`); C.text(w/2,40,'文字','sm','c','t'); C.done(el)"}
```

- 变量：`el` 画布元素、`w` 画布宽度（像素）、`PK` 工具包。
- `PK.Chart(w,h)`：`svg(片段)` 画形状，`text(x, y, html, 样式类, 水平对齐 l/c/r, 垂直对齐 t/m/b, 颜色)` 写文字，`done(el)` 输出。样式类：空（数值）、`sm`（小数值）、`ax`（坐标轴）、`xl`（类别名）、`xs`（小字）。
- 颜色用 `PK.ACC`（强调色）、`PK.PAL[i]`（分类色）、`PK.UD.up / PK.UD.down`（涨跌）、`PK.DIM`（灰）、`PK.mix(色, PK.W, 0.5)`（混白变浅）、`PK.ink(色)`（文字安全色）。
- 其他：`PK.niceTicks(lo, hi)` 刻度、`PK.yAxis(C, lo, hi, Y, 左边距, 右端, 单位)` 纵轴、`PK.fmt` 千分位、`PK.badge(公司键, 尺寸)` logo、`PK.legendHTML`、`PK.arcPath`。
- **文字一律用 `C.text`，不要写进 SVG 的 `<text>`**：导出 PNG 时 SVG 里拿不到网页字体。不要用 `box-shadow`（导出会变成色块）。
- 画完跑一次 `scripts/test_export.py` 确认导出正常。
