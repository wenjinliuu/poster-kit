# 从资料到海报：资料卡 → 分析 → 大纲

做海报最容易犯的错是“先有格子再填数”：不管这次的看点是什么，都按同一套栏目往里塞。正确的顺序是先把资料查全，再从资料里找出这次真正值得讲的问题，最后才决定版块和图。

三样东西都写成文件放在 spec 旁边（`research.md`、`outline.md`），改稿、做第二张图时直接复用。

## 1. 资料卡：记账本，不是筛子

资料卡只负责**把查到的东西都记下来，并标清楚是什么、从哪来**。这一步不做取舍，取舍在大纲里做。

规则：
- **全收**：事实、数字、观点、传闻、线索都记。不因为“不像重点”或“配方清单里没这一项”就不记；配方清单只是提醒别漏，不是查找范围。
- **标注，不删除**：传闻标“传闻”，观点写明是谁说的；几家数字不一致就都记下来，并写清口径差在哪，不替读者挑一个。
- **每条一行**：要点 + 口径 + 来源 + 日期。不贴原文，所以记得多也不会太长；条数不设上限（一次财报通常几十条）。
- **查不到的也记**：写“未披露”或“没查到”，避免后面用估算顶上。
- **奇怪的地方单独记**：数字和直觉对不上、市场反应和基本面对不上、管理层回避的问题——分析往往从这里开始。

格式（Markdown，栏目可按话题增删；下面的数字只演示写法）：

```markdown
# 资料卡：英特尔 2026 Q3 财报（截至 2026-10-30 08:00 北京时间）

## 事实与数字
- 营收 165.1 亿美元，同比 +21% ｜GAAP ｜公司新闻稿 2026-10-29
- 数据中心与 AI 部门营收 73 亿，同比 +78% ｜分部口径 ｜同上

## 预期与对比基准
- 一致预期：营收 165.0 亿、调整后 EPS 0.40 ｜LSEG ｜CNBC 转引 2026-10-29

## 观点（写清是谁说的）
- [管理层] CFO：Q4 毛利率受 Fab 28 停产影响约 2 个百分点 ｜电话会
- [券商] 某行：维持评级，目标价下调至 … ｜2026-10-30
- [社交] X 上主流看法：“业绩超预期、指引拖累” ｜抽样，非统计

## 传闻 / 未证实
- …（来源、日期）

## 数字对不上的地方
- 资本开支：公司口径 759 亿（现金）vs FactSet 773 亿（含融资租赁）

## 奇怪的地方 / 线索
- 本季营收、EPS 都超预期，盘后却跌 23% → 指引？毛利率？

## 未披露 / 没查到
- 18A 外部客户名单：未披露
```

## 2. 分析：从资料里找问题、找原因

1. **找主线**：这件事最重要的变化或意外是什么？用一句话写出来。读者只记住一件事的话，应该是这一件。它就是大标题。
2. **列问题**：读者看到主线会接着问什么？列 3～5 个。来源有两个：`recipes.md` 里这一类海报的“常问的问题”，和资料卡里“奇怪的地方”。问题按这次的重要程度排，不按配方顺序排。
3. **逐个回答，用比较和拆分找原因**：
   - **和什么比**：预期、公司指引、上季、去年同期、同行、自己的历史常态。一个数字单独看说明不了好坏。
   - **怎么拆**：量 × 价；分业务、分地区；利润一层层往下（收入 → 毛利 → 营业利润 → 净利润），看在哪一层出了变化；一次性还是经常性；汇率、会计口径。
   - **原因要有证据**：每个“因为”都能指到资料卡里的数据或出处；管理层的解释写成“公司称”。
   - **能不能持续**：指引、订单和在手合同、管理层表态、行业数据。
   - **市场反应和基本面对得上吗**：对不上本身就是一个问题（如“超预期却大跌”，答案常在指引、资本开支或估值里）。
4. **反方和不确定**：每个结论想一想有没有反例；拿不准的写“还不确定”或“市场有分歧”，不硬下结论。

边界：分析是解释“发生了什么、为什么、接下来看什么”。不给买卖建议，不预测股价；观点归到具体的人或机构；自己算的数标“测算”并写算法。坏消息和好消息一样讲清楚，不只挑一边。

## 3. 大纲：每个版块回答一个问题

```markdown
# 大纲
标题：英特尔三季报超预期 ｜盘后跌 23% ｜Q4 指引远低于预期，PC 疲软拖累
KPI：营收 165 / 调整后 EPS 0.52 / 毛利率 44.1% / Q4 营收指引 150–160

1. 问：超预期为什么还大跌？
   结论小标题：本季超预期，下季指引却低 9%
   证据：资料卡 预期 1–4 条、指引 2 条 ｜图：beat（本季实际 + 下季指引对一致预期）
2. 问：哪块业务在涨、哪块在拖？
   结论小标题：数据中心 +78%，PC 业务 −5%
   证据：分部营收 4 条 ｜图：bars（分部营收，高亮数据中心）
…
未用：资料卡里没进大纲的要点（一行一条，标“未用”）
```

规则：
- 一个版块回答一个问题，小标题写结论；顺序就是读者提问的顺序（主线 → 原因 → 影响 → 接下来看什么 → 市场怎么看）。
- 每个版块写出用哪几条资料、用什么图（按 `charts.md` 选）。没有资料支撑的版块删掉，不要为了版式完整去凑。
- 资料卡里没用上的要点不删，列在“未用”里。
- 深度海报（4 个版块以上）能和用户对话时，先把大纲给用户看一眼再画；无人值守时直接往下做。

## 4. 写 spec 之前过一遍内容关卡

- 大标题回答了主线，且是这次最重要的事，不是套话。
- 每个小标题是结论；读者只看小标题也能拿到要点。
- 每个数字都能在资料卡里找到出处和日期；估算、传闻都有标注。
- 好坏两面都讲了；拿不准的写了“不确定”。
- 资料卡里“奇怪的地方”要么在海报里回答了，要么在大纲“未用”里说明了为什么不放。

## 有专门的资料技能时

如果另有收集资料的技能（比如某个团队自己的数据源、关注重点），按它补充资料来源和问题，它的要求优先；资料卡、分析、大纲的格式仍按本文件。
